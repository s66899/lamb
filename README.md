# 🐑 助手工程师

把「多个 BOM 表里标红的改动件」拆成加工包,生成可直接发给加工厂的单文件看板,
并在源表或交付文件变动时**自动重建**。

多项目通用 —— 换项目只写一份 `项目配置.json`,不改代码。

---

## 两种用法

### 图形界面(推荐)

双击 `发布\助手工程师\助手工程师.exe`。

**启动后必须先选一个入口,才能进入下一步:**

| 入口 | 用途 |
|---|---|
| **📁 添加文件夹** | 导入一个已有的 BOM 表目录 —— 自动识别表结构,不用手填列号 |
| **✨ 新建项目** | 从零开始,建一个空的项目文件夹(把 xlsx 放进 `1_源数据` 再扫描) |

选完之后的项目工作台:

```
① 构建 BOM 表 + 看板        ② 实时监听(变动自动更新)      ③ 打开看板
扫描源数据   添加文件夹   新建项目   分类规则   打包交付   环境自检   ④ 导出核对版 HTML
```

左栏是各分类的零件数与到位情况,右栏是最近的更新日志。

---

## 完整工作流

```
① 构建           从源表读标红件 → BOM 表 + 实时看板
② 人工核对       用 Excel/WPS 打开 2_BOM表 里的表,随便改
                 改过的格子会标黄,后续更新不会被覆盖
③ 分类规则       开放段里加工件/标准件分不开时,勾选前缀与关键字
④ 导出核对版     从表格读出最终内容 → 单文件 HTML,发给别人
```

### 两个 HTML 的区别(重要)

| | ① 构建生成 | ④ 导出核对版 |
|---|---|---|
| 数据来源 | **源表** | **2_BOM表 里的当前内容** |
| 你的手动修改 | 不体现 | **完整体现** |
| 实时联动 | SSE 推送,变动自动重载 | 静态快照 |
| 用途 | 自己盯进度 | **发给加工厂 / 存档** |

所以「人工核对完之后导出 HTML」必须用 ④,否则你改的材料、数量、备注全都不在里面。

```bat
sheep export-html 我的项目                     REM 导出到 6_看板\
sheep export-html 我的项目 --out D:\桌面\       REM 或指定位置
```

导出文件名自动带时间戳,如 `改动零件看板_核对版_0929_2106.html`。
打开即用,单文件,不需要 Python、不联网、不带附属文件夹。

### 命令行

```bat
cd D:\助手工程师
sheep.cmd gui                       REM 图形界面
sheep.cmd new 我的项目
sheep.cmd import 我的项目 --source "D:\某个\BOM表目录"
sheep.cmd rules 我的项目 --auto
sheep.cmd build 我的项目
sheep.cmd bg   我的项目              REM 后台监听
```

exe 也支持命令行(加参数即可),例如 `助手工程师.exe doctor`。

## 打包成 exe

```bat
python 打包exe.py                 REM 文件夹版(启动快,推荐)
python 打包exe.py --onefile       REM 单文件版
python 打包exe.py --clean         REM 先清理再打包
```

产物在 `发布\助手工程师\`。要点:

- `--console` 打包,双击时程序内部 `ShowWindow` 隐藏黑框 —— 图形界面干净,命令行又有输出
- 打包后**项目目录跟着 exe 走**(即 `发布\助手工程师\项目\`),换位置不会丢项目
- 资源(看板模板)从 PyInstaller 的 `_internal` 读,项目/日志写在 exe 旁边
- 后台监听靠 `助手工程师.exe watch <项目>` 派生子进程,不依赖 .py 文件

## 项目文件夹结构(自包含,整个拷走就能换机器)

```
我的项目/
├─ 项目配置.json     源表路径 / 列位置 / 分类规则 / 交付物要求
├─ 1_源数据          把 BOM 表放这里(用「扫描源数据」导入)
├─ 2_BOM表           <分类>物料表.xlsx
├─ 3_3D图/<分类>/     放 STEP —— 这就是「3D 图」
├─ 4_2D图/            放 2D 图 / PDF —— 这就是「工程图」
│                     (平铺,不按分类建子目录)
├─ 6_看板/           改动零件看板.html(单文件,可直接外发)
├─ 7_归档/           备份区,只增不删 —— 东西不见了来这里找
│   ├─ 导入前备份_<时间戳>/    重复导入时被替换掉的旧版表
│   ├─ 同步前备份_<时间戳>/    与源同步时源里已不存在的文件
│   └─ 开发过程备份/           开发期间的备份(整理前快照/看板历史/改表前备份)
│                     —— 导入和同步都**以最新为准**,旧的搬进这里,
│                        不直接覆盖。详见 备份说明.md
├─ _基线             手动修改保护的基线快照
├─ _日志/更新.log
└─ _报告/手动修改冲突.txt
```

## 分类与顺序

固定顺序,**不混放**:

```
3D打印件 → 塑胶件 → 钣金件 → 机加工件 → 外购件
```

每类一张独立表,表内序号各自 `1..N`。顺序在配置 `categories.order` 里改。

判定顺序:

1. 源表里的**分类段行**(如「塑胶件」独占一行)→ 直接归该分类(`directSections`)
2. 开放段(如「机加件」)内细分:
   - 图号或名称含 `purchaseKeywords` → `purchaseCategory`(默认外购件)
   - 图号以 `machinedPrefixes` 开头 → `machinedCategory`(默认机加工件)
   - 都不命中 → `unmatchedCategory`
3. `dedupe` 里的分类跨样机去重,数量写成 `2+2+2=6`

`sheep rules` 会统计开放段里的图号前缀分布与标准件关键字命中,
`--auto` 一键写入并预览分类结果,`--interactive` 逐项挑选。

## 手动修改保护

表格你可以随便手动微调。下次更新时工具做**三方比较**:

| 情况 | 处理 |
|---|---|
| 你没动过 | 更新为源表新值 |
| **你改过** | **保留你的值**,该格标黄 + 橙边框,表标题显示 `⚠ N 处` |
| 你把格改成了工具的新值 | 视为已采纳,不再提示 |
| 你清空了某格 | 视为清空,不会保留旧的 |
| 源表新增了行 | 加进来 |
| 源表删掉了行 | 移除,并写进冲突报告 |
| 序号列 / 图示列 | 工具管理,**永不保护**(可安全重排) |

机制:每次成功落盘后,把**工具生成的值**存为基线(`_基线/<分类>.json`),
下次用 `基线 / 你手上的表 / 本次生成` 三方比对。
> 存的是工具的值而非合并后的值 —— 否则保护只生效一次,下次就覆盖你。

明细:命令行汇总 + 表标题提示 + `_报告/手动修改冲突.txt`

```bat
sheep build 我的项目              REM 正常更新(保护手动修改)
sheep reset 我的项目              REM 清空基线,按源表全量重建(丢弃手动修改)
```

⚠ **重建 BOM 表前请先关闭 Excel/WPS**,否则写不进去(会提示 `[被占用]`)。

## 实时更新

`sheep watch` 轮询(默认 2 秒)+ 去抖(文件稳定 1.5 秒后才动手,避免读到复制到一半的文件)。

| 变动 | 行为 |
|---|---|
| 源表 `.xlsx`(含 `bomSources` 里的) | **全量**:重出 BOM 表 + 看板 |
| 3D图/工程图/2D图 增删改 | **增量**:只刷看板(约 0.3 秒) |

> 源表变动检测扫的是 `sources` **和** `bomSources` 两者。
> 早先只扫 `sources`,而「导入已完工项目」的源表全在 `bomSources` 里 ——
> 改了 BOM 表,监听开着也不更新。指纹的 mtime 用 **纳秒**,
> 否则一秒内连续改两次(批量导入正是如此)会漏判。

## 手动检测刷新

不想开监听、只想按一次按钮知道「文件夹变了什么」时用:

```
界面:「检测文件夹变更」按钮
命令行: sheep detect <项目>          REM 识别变更并重建
        sheep detect <项目> --no-build   REM 只报变更不重建
```

扫源表 + 交付物目录,报四类变更:源表改动 / 源表改名 / 交付物新增、更新、移出。
有变更时按需重建(源表变 → 全量;只有交付物变 → 增量),无变更时跳过不白跑。

快照存在 `_基线\扫描基线.json`,所以**第二次点只报「上次之后」的差异**。
删除基线文件就相当于「重新扫描一次」。

看板工具栏那颗「**刷新**」按钮走的是同一个接口:

| 打开方式 | 行为 |
|---|---|
| 经本地服务(`http://127.0.0.1:<端口>/…`) | 先 `POST api/scan` 报变更明细,再带 `?t=<时间戳>` 重载 |
| 双击打开的静态文件 | 不请求服务端,直接重新读磁盘上那份 |

> 不带时间戳会命中浏览器缓存,点了跟没点一样。

> 能不能实时**按访问方式判断**(运行时看 `location.protocol`),不是构建时写死的标记 ——
> 否则「先构建、再用本地服务打开」这种最常见的用法反而拿不到实时。

`--serve` 会起本地服务(`http://127.0.0.1:8900/...`)并自动打开浏览器。
看板通过 **SSE(Server-Sent Events)** 接收推送,右上角有连接状态指示灯,
变动后自动重载 —— 不用手动 F5,也不用整页轮询。

可用地址：

| 地址 | 说明 |
|---|---|
| `http://127.0.0.1:<端口>/6_看板/改动零件看板.html` | 完整路径,`start_server` 自动打开的就是它 |
| `http://127.0.0.1:<端口>/` | 重定向到看板 |
| `http://127.0.0.1:<端口>/看板` | 短链接,好敲 |

> **中文短链接要两种都能认**（踩过的坑）：`do_GET` 若直接拿 `self.path`
> 和 `/看板` 比大小，两种到达方式都 404 —— 程序生成的是
> `%E7%9C%8B%E6%9D%BF`，地址栏手输是裸 UTF-8 字节，而 `unquote()`
> 只解 `%XX`。请求行是 latin-1，取回字节后要再按 utf-8 解一次。

> 直接双击 `6_看板\改动零件看板.html` 打开的是**静态快照**(给加工厂用)。
> 要实时联动就用 `--serve` 打开的地址。

## 数据从哪来:有 BOM 表就以 BOM 为主,没有才用零件表

导入一个文件夹时,工具先把每张表分成两类:

| 判据 | 归类 | 存到哪 |
|---|---|---|
| 表里有分类段(「机加件」「塑胶件」这种行内标题) | **零件表** | `1_源数据/` |
| 表里没分类段,但**文件名或工作表名**能认出分类 | **BOM 表** | `2_BOM表/<分类>物料表.xlsx` |

**BOM 表优先。**它是人工核对过的最终成果,图和链接都齐,是权威来源。
零件表只有 WPS 的 `DISPIMG` 公式图、没有超链接,拿它当准等于把内容退回去。

> **读取逻辑只有一份:`build_core.read_items(cfg, proj)`。**
> 构建、工作台零件总览、状态栏都必须走它,不要自己写
> `consolidate(extract(cfg))`。
>
> 踩过的坑:构建改成「有 BOM 表就以 BOM 为主」之后,工作台那边还留着
> 一份只认 `cfg["sources"]` 的老逻辑 —— 两份分叉的直接后果是,导入一个
> 只有 BOM 表的项目后,**构建能出看板,但工作台空空如也,标题还写着
> 「0 个源表」**。构建对不对一验就知道,界面这个洞更难发现。
>
> 同理,标题旁的表数用 `build_core.table_count(cfg)`
> (零件表 + BOM 表一起数),不要用 `len(cfg["sources"])`。

以前两类表被一起塞进同一份列表、按同一套逻辑读,导致导入「已完工项目」
(只有 `BOM表/` + `3D图/` + `2D图/`)时:

- **一张图都没有** —— 零件表用 `DISPIMG` 公式(图片在 xlsx 内部 `xl/media/`,
  `ws._images` 读出来是空的),BOM 表用真嵌入图片(`ws._images` 能读,
  但整张表一个 DISPIMG 都没有)。两条读取路径各只认一种,各丢一半。
- **一个链接都没有** —— `extract()` 根本不读超链接,只有「回读 BOM 表」
  那条路径读，而且还只读备注列。
- **分类整类丢失** —— BOM 表里没有分类段,分类只写在文件名/工作表名上。
  实测 5 张 BOM 表读出来变成「外购件 58 + 机加工件 32」,
  3D打印件/塑胶件/钣金件**整类消失**。

现在:两种图片机制(`DISPIMG` + 嵌入图片)一起收、谁有给谁;超链接按行扫描
全部数据列(优先备注列);分类先看文件名/工作表名,再看段名,最后才走关键字细分。
零件表路径也一并修好了 —— 导入 4 张零件表,126 件**全部有图**、46 条链接。

校验:`import_e2e` 之后还有 `data_test`(24 项)专门钉死这四件事,
源表只读,产物落 TEMP。

## 看板功能

- **面板**:总数 / 各交付物到位率 / 缺件 / 数据待补 / 带图示
- **分类维度概览**:总卡片下面一条,逐分类给出「N 件 · 缺 M · 齐套 X%」,
  不用展开表格就知道是哪一类拖后腿
- **三个可折叠区块**(点标题展开,默认只展开「零件明细」):
  - **缺失清单** —— 一行一件,列出分类 / 样机 / 图号 / 名称 / 缺什么 /
    期望存放路径 / **相近文件**;`复制缺失清单` 一键导出
  - **数据检查** —— 缺图号/名称/材料/数量、数量非数字、无图示、图号重复、
    **跨分类重复**(同一零件被拆进两个分类,会重复采购)、
    **交付物名字对不上**、**开放段细分不出**;点标签复制明细
  - **零件明细** —— 内含各分类小节,按固定顺序排列,每节独立折叠
- **图示列直接摆缩略图**(80×56,`object-fit:contain`),点一下居中弹出大图
  (`Esc` / 点遮罩 / 点右上角 × 都能关;点图本身不关,方便右键另存)
  - **必须是 `contain` 不能是 `cover`** —— 零件图有宽有窄,cover 会把窄图两边
    裁掉,看着像另一个零件
  - 缩略图带 `loading="lazy"`,91 张大图不至于一次性解码卡住页面
- **交付物点一下直接打开文件**(`<a href>` + `target="_blank"`)
  - 路径必须过 `fixPath()`:Python 的 `relative_to()` 给的是**反斜杠**
    (`3_3D图\塑胶件/x.STEP`),浏览器 URL 里反斜杠不算分隔符;
    看板在 `6_看板\` 下、文件在 `3_3D图\` 下,还要补 `../` 退一级。
    少任一条就是「点开跳转失败」
  - 全局 click 处理里必须 `if(t.tagName!=='A')` 才复制路径,
    否则 `return` 掉默认行为,链接点了没反应
  - 缺件那几行仍是 `<span data-p>`,点了复制期望路径方便排查
- **快速核对**:每行 `✓ 已到位` / `✗ 缺`。徽章上还标出**匹配方式**
  (精确 / 前缀 / 去尾缀 / 子串 / 平铺),知道自己是怎么被认出来的
- **交付物三态**:`✓ 已到位` / `✗ 缺` / `— 不需要`。
  「不适用」和「需要但没文件」是两回事,混在一起清单全是假警报
- **源表手工标注**(STEP / 出工程图STEP / 新 / 改)会带进看板,
  单独成列,配合筛选「仅有标注」快速找出人在表上点过名的那几件
- **来源表**列标出这一行来自哪张表,排查重复/冲突时必需
- 搜索 + 筛选:全部 / 仅缺文件 / 已齐套 / 仅有标注;
  `展开全部分类` / `收起全部分类` / `复制缺失清单` / `复制数据问题` /
  `导出 CSV`(加工厂拿表格对料用)
- 顶部黄条提示本次更新保留了多少手动修改、移除了多少行

## 交付物需求怎么判定(改配置前先看这段)

交付物只有**两类**,不再拆成「STEP零件 / 工程图 / 2D图」三个:

| 键 | 看板上叫 | 目录 | 扩展名 |
|---|---|---|---|
| `step` | **3D图(STEP)** | `3_3D图/<分类>/` | `.step` / `.stp` |
| `2d` | **2D图(工程图)** | `4_2D图/` | `.pdf` / `.dxf` / `.dwg` |

**工程图就是 2D 图。**以前单开一个 `4_工程图`,等于让人以为有两种东西
要交,文件放错目录还查不出来。老项目里的 `4_工程图` / `5_2D图`
在下次打开项目时会自动并进 `4_2D图`(搬完才删,失败不丢文件),
老配置里的 `dwg` 键也会自动改名成 `2d`。

一件东西要不要出 3D 图 / 2D 图,由**两个来源叠加**决定,看板上的
`✓ / ✗ / —` 三态就来自这里:

1. **分类白名单**(`deliverables.<key>.cats`)—— 主规则。
   默认 `step` 覆盖 机加工件/塑胶件/钣金件/3D打印件,`2d` 覆盖 机加工件/钣金件。
2. **源表手工标注**(`extract.markColumns`,默认 I/J/K/L 列)—— 叠加,
   用来覆盖白名单说不了的情况。标注里出现 `STEP/3D/三维` 就要求 3D 图;
   出现 `2D/dwg/dxf/pdf/图纸` 才要求 2D 图。

**「出工程图STEP」是一个整体说法,意思是"出工程图的 STEP",即 STEP 而不是 PDF。**
所以 `2d` 的关键字里刻意**没有**「工程图」——否则会凭空多出一个
永远补不上的 2D 图需求(马桶项目 `mtb-01`「马桶壁」就是这种)。

标注与白名单冲突时(标注说要出、但分类不在 `cats` 里),工具**以标注为准**
临时放行,同时在「数据检查」里报一条 warn 提示去改 `deliverables.<key>.cats`,
让配置漏项自己浮出来,而不是悄悄把要求吃掉。

`2d` 默认 **不按分类建子目录**(`subfolder: false`),和历史项目一致 ——
2D 图平铺放在 `4_2D图/` 根下。按分类建了子目录的话,整批工程图会被判成
「缺失」(实测 51 个需求一个都匹配不上)。文件多到需要分类时,
在项目配置里把 `subfolder` 改成 `true` 即可。

查找顺序:先在期望目录找,找不到再回交付物根目录找一遍;
两种存放方式都能认。匹配方式会标在看板徽章上。

读别人(或旧版自己)做的 BOM 表时,表头写的是老名字,所以每种交付物都配了
`aliases`:`step` 认「STEP零件/STEP/3D图/3D/三维图」,`2d` 认「工程图/2D图/2D/图纸」。
不认这些的话,读回来的表一个交付物都识别不出,看板会显示「零需求」——
明明表里写着 42 个 STEP。

## 分类怎么细分「开放段」

源表里的段(如「机加件」)是**开放段**:里面既有标准件也有自制件,
光看段名分不出来,只能按规则细分。规则在 `categories` 里,按顺序判:

1. 名称/图号含 `purchaseKeywords` → 外购件(优先级最高。
   「涡轮轴端盖垫片」名字里有「垫片」,那是要买的垫片,不是要铣的板)
2. 图号以 `machinedPrefixes` 开头 → 机加工件
3. 名称含 `machinedKeywords` → 机加工件(前缀表覆盖不到时的兜底)
4. 都不中 → `unmatchedCategory`(默认外购件)

**第 4 步会在「数据检查」里报出来**(标签:「机加件细分不出」),
列出图号让你去补前缀表。以前这里是静默的:件被归到「外购件」,
看起来像要买的,实际是要自己加工的 —— 这类漏项最难发现。

改前缀表时注意别收太宽的词:「水管」「软管」这类词会把
「污水管支撑B」这种机加件误抓进外购件(已从默认表里去掉)。

校验方法:拿一份人工核对过的旧看板当基准,把它的图号喂给 `classify_detail()`,
看分类一致率。当前默认配置在马桶项目开放段 71 条上 **71/71 一致**。

## 新建 BOM 表:用标准模板,别从零画

自己新建表最容易出两类错,而这两类错**都不会报错** —— 表照样能打开,
只是看板上一片「缺件」「无图」,很难查到是表的问题。

**取模板**(界面工作台点「取 BOM 模板」会直接放到桌面,或命令行):

```bash
sheep.py template --out D:\某个目录     # 模板 + 说明 md
sheep.py template --doc --out 目录      # 只取使用说明
```

模板在 `templates/`,打包 exe 时会自动带进去。

### 模板长什么样

```
行1   标题(整行合并)
行2   表头(每列纵向合并,占 2、3 两行)   ← 行3 是表头占位,是空的
行4   第一行数据                        ← 数据必须从第 4 行开始
```

| 列 | 名称 | 说明 |
|---|---|---|
| 1 | 序号 | |
| 2 | 图示 | 插图片。**两种都认**:直接插入图片,或 WPS 的 `=DISPIMG("ID_...",1)` |
| 3 | 图号 | **必填**,零件的唯一标识 |
| 4 | 名称 | **必填** |
| 5 | 材料 | |
| 6 | 数量 | |
| 7 | 工艺 | |
| 8 | 备注 | 加 http/https 超链接 → 看板自动显示「采购链接」 |
| 9 | 意图标注 | 手工标注(STEP / 新 / 改…),看板单独成列,可筛选 |
| 10 | 样机 | A / B / C,或「ABC通用」。留空按 A |
| 11 | **3D图(STEP)** | 填文件名 = 需要(计入齐套率);**留空 = 不需要** |
| 12 | **2D图(工程图)** | 同上 |

每个表头单元格都挂了**批注**,鼠标悬停就能看到该列的注意事项。

### 六条红线

1. **不要删列、不要调列序。** 列位置在 `项目配置.json → extract` 里写死,工具**按位置**读
   序号/图示/图号/名称/材料/数量/工艺/备注,不按表头文字。
2. **交付物两列的表头文字不能改。** 这两列是**按表头文字**认的(和上面相反),认得:
   - 3D图:`3D图(STEP)` / `STEP零件` / `STEP` / `3D图` / `三维图`
   - 2D图:`2D图(工程图)` / `工程图` / `2D图` / `2D` / `图纸`

   写成「3D模型」「二维图纸」这类 → **认不出来**,看板一片「零需求」,哪怕文件名填了。
3. **文件名必须带分类名**,如 `机加工件物料表.xlsx`,**工作表名也写成 `机加工件`**。
   分类是**由文件名或工作表名决定的,不看表里的内容**。
4. **不要放「分类段行」**(整行有内容但序号列和图号列为空)。放了整张表就不再被当作
   BOM 表,优先级掉到零件表那一档,图片和链接都会丢。模板里不需要分类段。
5. **交付物列留空 ≠ 填了但文件没交**:
   - 留空 → 看板显示「— 不需要」
   - 填了但文件不存在 → 看板显示「✗ 缺」,**计入齐套率**
6. **第 9、10 列的标注只存在于源表。** 产出表丢了、源表又没同步,就再也回不来。

完整的注意事项在 `templates/BOM表模板说明.md`,或模板旁边那份 `_说明.xlsx`。

> 这套模板不是照印象画的,是照工具**实际**的读取逻辑做的,并且做了**反证测试**:
> 把交付物表头故意改成「三维模型(随便写)」,确认工具确实认不出来 ——
> 证明识别真的靠表头文字,不是碰巧。

## 导入别人的项目时会自动探测什么

`sheep import` 打印每个候选表的探测结果,无需手工指定:

- 工作表(挑红底最多、数据最全的那张)
- 表头行 / 数据起始行 / 参与列数
- **「新改动」标记列**:统计每列的红底单元格数量取最多;
  若有多个列数量接近(比如表被改过、标记列挪了位),**会列出全部候选让你选**,
  命令行可用 `--red-column 8` 强制指定
- **分类段列**(某列有值而序号列、图号列为空的行)与段名列表
- 各功能列:序号 / 图示 / 图号 / 名称 / 材料 / 数量 / 工艺 / 备注(按表头文字模糊匹配)
- 是否有 WPS 单元格图片(DISPIMG)
- 样机标记(从目录名或文件名猜 A/B/C)

探测不准时可以手动改 `项目配置.json` 的 `extract` 段。

### 导入会复制什么(以及**不会**复制什么)

| 源目录 | 处理方式 |
|---|---|
| `BOM表/*.xlsx` | 复制到 `2_BOM表/<分类>物料表.xlsx` |
| `1_源数据/*.xlsx` | 复制到 `1_源数据/` |
| `3D图/**` `.step .stp .igs .iges .sldprt` | 复制到 `3_3D图/`，**保留分类子目录** |
| `2D图/**` `.pdf .dwg .dxf` + `.png .jpg` | 复制到 `4_2D图/` |
| `2_BOM表/ 3_3D图/ 4_2D图/ 6_看板/ 7_归档/` | **跳过** —— 这些是助手自己的产出,不是源 |

> 以前 `3D图`/`2D图` 也在跳过名单里,导致源目录里的 STEP/PDF **一个都没进项目**,
> 导入完看板一片缺件。现在按扩展名归位,实测 69 个交付物全部复制到位。

### 重复导入:最新为准,旧的归档

对同一个项目再导入一次时:

- **内容变了**(MD5 不同)→ 旧文件搬进 `7_归档/导入前备份_<时间戳>/`,然后新的写入
- **内容没变** → 跳过,不归档不重写

> 归档只看**有没有真的变**。早先不看内容就归档,结果重复导入没改动的目录时,
> 归档里堆满同一个文件的多份副本,而真正那份「旧版本」被顶掉了 ——
> 查归档时全是新版,像是归档功能坏了。

## 界面设计系统(`theme.py`)

视觉全部收敛在这一个文件,界面代码只引用语义名,不再散落色值。
改配色/圆角/动效只需要动 `theme.py`。

```
色板      T.BG / T.CARD / T.CARD_HI / T.SHEET / T.LINE / T.FG / T.FG2 / T.FG3
          T.ACC / T.OK / T.WARN / T.BAD   —— 语义色,不含写死的十六进制
字体      T.font(size, weight, mono) / T.display() / T.TITLE / T.T_BODY / T_TINY …
尺寸      T.S1..S8(4/8/12/16/20/28/36/48)  T.R_SM/MD/LG/XL/PILL
动效      T.Tween(控件, 毫秒, 每帧回调).start(ease)
          T.ease_out_cubic / T.ease_in_out / T.spring(有回弹,iOS 的手感来源)
组件      T.Card 圆角卡片(自动高度)  T.Pill 胶囊按钮  T.Segmented 分段控件
          T.Switch 开关  T.SkeletonLine 骨架屏  T.aline/hline 分隔线
```

### Tk 在这上面踩过的坑(改 theme 前先看)

1. **Tk 不支持 8 位十六进制颜色**。`#0000003D`(带 alpha)会直接报
   `invalid color name`。阴影/半透明底色一律用实色近似分层。
   `T.audit_colors()` 会在启动时自检。
2. **Tk 的 `font` 选项不接受字体栈列表**。传 `('Segoe UI','雅黑',13,'bold')`
   报 `expected integer but got a list` —— 只能给一个字体名,
   中英混排靠 Tk 自己回退。
3. **宽度必须用 `T.measure()` 量,不能用 `len(text)*8`**。
   Canvas 没有 `font measure` 子命令;按字符数估算在混排下会少算 60%
   (实测 128 vs 真实 210),按钮文字就会溢出胶囊。
   `measure()` 借一个离屏 Canvas 画一次读 bbox,拿到的是真实渲染宽度。
4. **`self._w` / `self._h` 不能拿来存控件宽高** ——
   `_w` 是 `tkinter.Misc` 存放控件路径名的内部属性,覆盖后
   `pack()` 会报 `bad argument "44": must be name of window`。
   画布组件统一用 `_cw` / `_ch`。
5. **同一父容器不能把同一个控件 pack 两次**,也不能混用 `place` 父容器
   + 子控件 `grid`。`_page()` 的内容层用 `place`,内部一律 pack/grid。
6. **`T.font` 的 weight 只能是 `normal` / `bold`**。
   传 `"regular"` 报 `unknown font style "regular"`;
   `theme.font()` 负责归一化,别绕过它直接构造元组。
7. **自绘圆角坐标要取整**。Canvas 多边形不接受 float 混排,
   统一走 `rounded_points()` / `capsule_points()`(内部已 round)。
8. **胶囊的两个半圆必须朝相反方向绕**(左 90°→270°,右 270°→90°)。
   早期版本两个都从 180°→360°,多边形自交画出来是个怪 blob。

### 打包时别漏掉 theme.py

`打包exe.py` 里 `theme.py` 同时出现在两处,缺一个 exe 就起不来:

```
HIDDEN = [..., "theme"]                    # --hidden-import
for item in (..., "theme.py"):             # 复制进 _打包 工作目录
```

`gui.py` 是 `import theme as T` 直接引用,PyInstaller 的静态分析虽然能扫到,
但这个文件**必须留在源码清单里**,否则生成的 exe 一双击就
`ModuleNotFoundError: theme`。打包后建议这样验一下:

```powershell
# 解包 PYZ 确认 theme 在里面
python -c "import sys,os,tempfile; sys.path.insert(0,r'<site-packages>'); from PyInstaller.archive.readers import CArchiveReader,ZlibArchiveReader; c=CArchiveReader(r'<exe>'); t=os.path.join(tempfile.gettempdir(),'v.pyz'); open(t,'wb').write(c.extract('PYZ.pyz')); print('theme' in ZlibArchiveReader(f'{t}?0').toc)"
```

### 窗口显示必须验收

`gui.present()` 是所有 Toplevel 的统一出口。它做三件事:
释放上一个窗口遗留的 grab → `transient` → `deiconify/lift/focus_force` →
`grab_set`(失败降级)→ **最后验收窗口确实可见**。

不可见就抛出带原因的 `RuntimeError` 并销毁窗口,绝不闷声吞掉。
旧版各窗口直接一路 `grab_set()`,任一步抛 `TclError` 都会中断后续步骤,
留下一个 `state=withdrawn`、尺寸 1×1、屏幕上什么都看不见、
但 grab 已经挂上导致整个界面失去响应的窗口 —— 用户看到的就是「点了没反应」。

构造 Toplevel 一律走 `gui.open_window()`,失败时销毁半成品。

### Toplevel 子类里别用 `self.` 调 App 的方法

`ImportWindow` / `RulesWindow` 是 `tk.Toplevel`,`self` 是**它们自己**,
不是 `App`。调 App 上的方法必须写 `self.app.xxx()`。

真实踩过的坑:`ImportWindow._do()` 里写了 `self._run_bg(...)`,
而 `_run_bg` 定义在 `App` 上 —— 一点「导入并继续」就抛
`AttributeError: 'ImportWindow' object has no attribute '_run_bg'`。
异常被 `_install_excepthook` 吞进 `日志/崩溃.log`,**界面上毫无反应**,
用户只会说"点了没反应"。

审计脚本(改完 Toplevel 类后跑一遍):

```python
# 找出所有 Toplevel 子类里 self.<App方法> 且自身没定义的调用
app_methods = {m.name for m in 类App的body if isinstance(m, ast.FunctionDef)}
for 每个 Toplevel 子类:
    for node in ast.walk(类):
        if isinstance(node, ast.Attribute) and node.value.id == "self" \
           and node.attr in app_methods and node.attr not in 自身方法:
            报警
```

### 项目名推断

`ImportWindow` 的默认项目名优先取表名里的「xx项目/xx工程/xx加工包」,
其次取去掉「源表/BOM表/物料表」后缀的目录名,最后退回第一张表的文件名
(会剥掉「(样机A)」「9-28」这类标记)。目录叫「源表」「BOM」这类
没信息量的名字不会直接当项目名用。

## 已知限制

- 打开中的 Excel/WPS 会生成 `~$xxx.xlsx` 锁文件,已自动忽略;但**写表前需关闭表**。
- 图示是 WPS 的 `DISPIMG` 单元格图片,需从 xlsx 内部 zip 里取,openpyxl 读不到。
  若源表用的是普通嵌入图片(openpyxl 可读的 `xls/media`),目前不会自动提取。
- 看板内嵌全部图片,零件上千时文件会到几十 MB,可先用 `sheep build --html` 单独出一版。
- **文件名和图号对不上时只提示、不自动挂载**。实测马桶项目源表图号写的是
  `gl-01`/`mtb-01`/`pz-a-3`,真实文件名却是 `AGL-01_1.STEP`/`AMTB-01_1.STEP`/
  `APZ-A-3_1.STEP`(少了首字母 A)。旧工具靠宽松匹配悄悄算成齐套,挂对了是运气,
  挂错了没人知道。这里只在「缺失清单」的**相近文件**列和数据检查里列出来,
  要你确认后改文件名或改源表图号 —— 挂错文件比报缺失危险得多。
- **跨分类重复需要人工裁决**。同一图号/同名件同时出现在两个分类
  (实测 `QB-XJQ` 在 3D打印件和塑胶件、`AMIFENGDIAN`/`GUAGOUDING_9B_改`
  在塑胶件和钣金件),工具只报「跨分类重复」,不会替你删掉一个 ——
  哪个该留只有你知道。

## 改看板模板前必看:`看板.html` 的 CSS 一断,后面全废

浏览器遇到**没闭合的 `{`**,会把从那一行往后的**整张样式表**全部丢掉。
页面看着还能打开,只是少了一堆样式,而且几乎不可能联想到是 CSS 断了。

实际踩过一次:给 `table` 加 `min-width` 时把整行替换成了
`table{width:100%;border-collapse:collapse;`(少了闭合),
结果 `th` / `td` / `.thumb` / `#lb` / `.toast` / `.mtab` **全部失效**。
最明显的症状是**大图灯箱跑到页面最下面** —— 因为 `#lb` 没拿到
`position:fixed`,被当成普通块级元素渲染在文档末尾。
当时完全没往 CSS 上想,只觉得"图片怎么在最下面"。

所以:

- **打包前会自动自检**。`打包exe.py` 里的 `_check_template()` 检查
  花括号是否配平、关键规则是否齐全;`tpl_test.py` 是同一套检查的独立版本。
  配平就**直接中止打包**,不会产出一个样式残缺的 exe。
- 手工改模板后也可以单独跑:`python tpl_test.py`
- 新增样式时,不要改动已有规则的整行 —— 用「在规则后面另起一行追加」的方式,
  避免手滑把整行替换掉。

## 界面线程规则(改过几次坑,改代码前先看这段)

Tkinter 不是线程安全的,而且**主线程没进 `mainloop` 时,从子线程调任何 tk 方法
(包括 `after`)都会抛 `RuntimeError: main thread is not in main loop`**。
这个错不会让程序崩,只会让界面停在某个中间状态不动 —— 看起来就是「卡死」。

所以有三条硬规矩:

1. **子线程绝不碰 tkinter。** 只往 `self._ui_q`(`queue.Queue`)里塞闭包,
   由主线程的常驻心跳泵 `App._tick` 每 100ms 排空后执行。
   心跳泵必须**常驻**,不能「队列空了就停」—— 子线程可能几秒后才投递,
   泵一停就再没人接手,界面会永远停在「正在读取…」。
   用 `App.post_ui(fn)` 投递,不要自己写 `threading.Timer` + `after`。
2. **耗时活一律进 `_run_bg()`。** 构建 / 导入 / 打包 / 扫描 / 自检
   都在后台线程跑,进度窗只是 `post_ui` 的消费者。
3. **进度窗永远可关。** 关掉只是不看输出,任务照常跑完,`on_done` 仍会执行。
   旧版把 `WM_DELETE_WINDOW` 绑成 `lambda: None`,任务一挂窗口就再也关不掉。

出错时看 `日志/崩溃.log`。`App._install_excepthook` 装的是全局
`sys.excepthook`,任何 Tk 回调异常都会弹窗 + 落盘,不会再静默失败。

### 并发与文件写入

监听进程、界面上的「构建」、命令行的 `build` 完全可以同时跑。
实测三个并发 `build` 时出现过这三类损坏,现在都处理了:

| 现象 | 原因 | 处理 |
|---|---|---|
| `项目清单.json` → 「注册表损坏」 | 两个进程同时写注册表,其中一个读到半截 | `paths.atomic_write_*` + `paths._reg_lock()` 跨进程锁 |
| `_图片缓存/*.png` → `cannot identify image file` | 同上,图片缓存被读到半截 | `atomic_write_bytes` |
| 看板 HTML 打不开 | 直接 `write_text` 写到一半 | `atomic_write_text` |

规则:

1. **写文件一律用 `paths.atomic_write_text/bytes`**,不要用 `write_text`
   —— 「写临时文件 + `os.replace`」才是原子替换,读到的永远是完整旧版或完整新版。
   `openpyxl` 的 `wb.save()` 同理:先存临时名再 `os.replace`。
2. **同一项目的构建要串行**:`run_build()` 已经套了 `build_lock`(msvcrt 独占锁),
   拿不到锁会排队等;等太久(默认 30 分钟)会打印警告后强行继续,
   **不会永久卡死**。
3. **注册表的「读-改-写」必须在 `_reg_lock()` 里**,原子写只保证文件完整,
   不保证不丢更新。
4. `subprocess.run` 调 `taskkill` 之类**必须给 `timeout`**,否则对方卡死
   会把界面线程一起锁住。
5. **命令失败要返回非 0 退出码**。`main()` 里是
   `rc = a.fn(a); sys.exit(0 if rc is None else int(rc))` ——
   cmd 返回 `None` 算成功,返回 `1` 算失败。不要用裸 `return` 表示失败。

   注意 `run_doctor()` 返回的**已经是退出码 0/1,不是布尔**。
   别写成 `return 0 if run_doctor() else 1` —— 那会把「一切正常(0)」
   当成假值,自检明明全绿却退出 1(这个 bug 实际发生过)。
   约定:返回 `None`/`0` = 成功,`1` = 失败,`None` 才是「没意见」。

### 项目定位

`sheep new <名> --path <目录>` 里的 `--path` 是**项目目录本身**,
不是父目录 —— 建出来就在 `<目录>` 下,不会再套一层 `<名>`。
`new` / `import` 已改走 `resolve_project()`,会查项目注册表,
所以用 `--path` 建在别处的项目,后续 `build` / `status` / `import`
只按名字也能找到。`find_project` 还做了大小写不敏感匹配,
找不到时会列出候选项目名。

### 窗口构造的坑

`Toplevel.__init__` 里抛异常时,Tkinter **不会**回收那个半成品窗口 ——
它留在屏幕上、控件建了一半、点不动也关不掉。统一走
`open_window(ImportWindow, ...)` 构造,失败时自动销毁再抛。

`ImportWindow` 曾经连续踩了两次,导致这个窗口**从来没成功打开过**:

- `_cb()` 硬编码 `font=` 却又收 `**kw`,调用处一传 `font=` 就
  `TypeError: got multiple values for keyword argument 'font'`。
  现在用 `kw.setdefault("font", ...)`。
- `ttk.Radiobutton(background=..., selectcolor=...)` →
  `TclError: unknown option "-background"`。ttk 组件**不接受**
  `background / bg / activebackground / activeforeground / selectcolor /
  highlightthickness / bd / borderwidth / relief`,
  要自定义底色就得换 `tk.` 版(`foreground` 和 `font` 是 ttk 合法的)。
  文件头 `_cb()` 的注释就是为这个存在的。

### 复现/回归

`refresh_status` 这类「后台读表 → 回主线程刷 UI」的路径,
单测里如果不用 `mainloop()` 而是 `update()` 轮询,
要注意 `after` 需要真实时间流逝才触发,断言前请轮询等待而不是固定 `sleep`。

**新增窗口必须用「真实构造」测,不能只测方法存不存在。**
只 `hasattr(ImportWindow, "show")` 是不够的 —— `show` 存在不代表
`__init__` 能跑完。测试里要用 `open_window()` 真建一次、点一下勾选框、
再 `destroy()`。ttk 的选项错误只会在构造那一刻炸。
